

* [Sigstore](https://www.sigstore.dev/) is a collection of open source tools that can be used individually or in concert to improve your software supply chain security. The Sigstore framework empowers software developers and consumers to securely sign and verify software artifacts.

**Sigstore** is the broader project/initiative — a set of tools and infrastructure aimed at making software signing easy, free, and verifiable, without requiring you to manage your own long-lived cryptographic keys manually (traditionally a major pain point in software signing).

* [cosign](https://github.com/sigstore/cosign):  is the primary tool/implementation within the Sigstore project.



> Sigstore is the whole system. Cosign is the CLI tool that talks to it.


## What is sigstore and cosign

Sigstore is the infrastructure — a set of public services (Fulcio, which issues short-lived certificates tied to your identity, and Rekor, the public transparency log that records every signature). It's the thing that actually does **keyless** signing under the hood.

Cosign is the command-line tool a developer runs (`cosign sign-blob`, `cosign verify-blob`) that acts as the client for that infrastructure. You never talk to Fulcio or Rekor directly — cosign handles that communication for you.

So: Sigstore = the backend/protocol. Cosign = the tool you actually type commands into. Same relationship as, say, Docker Hub (the registry) and the `docker` CLI (the tool you use to push/pull from it).


## Traditional (Key-based) vs Keyless


**Traditional (key-based) signing, e.g. GPG:**

- You generate a private key once, keep it on your laptop/USB/hardware token forever.
- You must protect it, back it up, never leak it.
- If it leaks, every past _and future_ signature made with it is now suspect — you have to revoke and re-issue.
- Verifiers need to somehow know your public key is really yours (web of trust, keyservers, etc.) — this is the part that "almost nobody does well," per your slides.

**Keyless (Sigstore/cosign):**

- No key to generate or store at all.
- Each time you sign, cosign asks Sigstore's Fulcio service for a _brand new, short-lived_ key pair, tied to an identity you already have (GitHub login, or the GitHub Actions workflow identity) via OAuth/OIDC login — no new secret to protect.
- That key pair expires in minutes and is discarded.
- Instead of "here's my public key, trust me it's mine," verification works by checking: "was this signed by someone who could authenticate as this identity, at this moment, according to the public Rekor log" — identity verification is outsourced to GitHub's login system, which you already trust.




## Main concept


**Release**: a tagged (commit that tagged), packaged version of your software (e.g. `v1.0.0`).
**Signing it**: proves that exact package is authentic and untampered — done via **Sigstore** (the trust infrastructure — identity verification + public transparency log), using **cosign** (the CLI tool you/your CI actually run to talk to Sigstore).
**Verification**: anyone downloading the release can run `cosign verify-blob` to check the signature against Sigstore's public record, confirming: _this file matches what was signed, by the identity it claims (your workflow), at that time._


> That's the whole chain: **release → signed via cosign → trust anchored by Sigstore → checked by anyone via verification.**




## The point of it 


- **Proves your release is authentic and untouched** since you published it
- **No secret keys for you to manage or leak** (keyless — identity comes from your GitHub login/workflow)
- **Publicly, permanently verifiable** by anyone, in seconds, via Rekor's log.
- **Stops tampering/impersonation attacks** — the exact defense against things like the xz backdoor





## How to do it ? (2 ways)

### 1) Locally on your machine
* Signed and trusted via your github account

```bash

# Install cosign
brew install cosign   # or: go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# Build the archive from your tag
git archive --format=tar.gz -o release.tar.gz v1.0.0

# Sign — opens a browser, you log into GitHub
cosign sign-blob --yes \
  release.tar.gz \
  --output-signature release.tar.gz.sig \
  --output-certificate release.tar.gz.pem
```

Then manually upload all three files (`release.tar.gz`, `.sig`, `.pem`) to your GitHub Release page yourself.

Verify command uses your identity:
```bash
cosign verify-blob \
  --certificate-identity 'your-github-email@example.com' \
  --certificate-oidc-issuer 'https://github.com/login/oauth' \
  --signature release.tar.gz.sig \
  --certificate release.tar.gz.pem \
  release.tar.gz
```
### 2) Github actions 
 * Automated via VM's, that upload the `.seg` and `.pem` to your github project releases.


The `release.yml` workflow does everything:

Example of a release.yml

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'

permissions:
  contents: write   # to create the GitHub Release and upload assets
  id-token: write    # required for cosign keyless (OIDC) signing

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@08eba0b27e820071cde6df949e0beb9ba4906955 # v4.3.0

      - name: Build release archive
        run: git archive --format=tar.gz -o release.tar.gz "${{ github.ref_name }}"

      - name: Install cosign
        uses: sigstore/cosign-installer@6f9f17788090df1f26f669e9d70d6ae9567deba6 # v4.1.2

      - name: Sign release artifact
        run: |
          cosign sign-blob --yes \
            release.tar.gz \
            --bundle release.tar.gz.bundle

      - name: Create GitHub Release with signed assets
        uses: softprops/action-gh-release@3d0d9888cb7fd7b750713d6e236d1fcb99157228 # v3.0.2
        with:
          files: |
            release.tar.gz
            release.tar.gz.bundle
```


Then tag and push:
```
git tag v1.0.0
git push origin v1.0.0
```

GitHub spins up a VM, runs the workflow, which builds the tarball, signs it, and uploads `.tar.gz` + `.sig` + `.pem` to your Releases page automatically — no manual steps.

Verify command uses the workflow identity:

```bash
cosign verify-blob \
  --certificate-identity 'https://github.com/AhmadAL-Quraan/Inception/.github/workflows/release.yml@refs/tags/v1.0.0' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --signature release.tar.gz.sig \
  --certificate release.tar.gz.pem \
  release.tar.gz
```
