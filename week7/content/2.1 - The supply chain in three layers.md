

## **Dependency confusion (Dependency-on-itself attacks): 

A dependency confusion attack exploits the way software dependencies are managed and resolved by **automatic package managers**. It occurs when **attackers deploy malicious packages with the same name as legitimate packages on public repositories**, so the main reason is the organization doesn't use a private registry for it's packages. 
## **Build-process attacks**

are security breaches where malicious code is injected into software during compilation or packaging, such as in CI/CD pipelines, bypassing source code controls.

## **Distribution attacks**

You build software (say, a Docker image or a binary) and publish it — push to a registry, upload to GitHub releases, whatever. The attack: **someone tampers with the artifact _after_ you built it but before the user downloads it**. could be: 
	- Registry compromised → attacker swaps your image with a malicious one
	- MITM on the download
	- Malicious mirror serving a modified copy


### The attack

You build software (say, a Docker image or a binary) and publish it — push to a registry, upload to GitHub releases, whatever. The attack: **someone tampers with the artifact _after_ you built it but before the user downloads it.** Could be:

- Registry compromised → attacker swaps your image with a malicious one
- MITM on the download
- Malicious mirror serving a modified copy

The user pulls something that looks legit but isn't what you actually built.

### The defense: Sigstore

Sigstore is a set of free, open tools (backed by OpenSSF) to **sign artifacts cryptographically** so consumers can verify "this exact artifact came from this exact build, unmodified."

Key pieces:

- **cosign** — CLI tool to sign/verify container images and other artifacts
- **Fulcio** — a certificate authority that issues short-lived signing certs, tied to an OIDC identity (your GitHub login, GitHub Actions workflow identity, etc.) instead of you managing long-lived private keys yourself
- **Rekor** — a public, tamper-evident transparency log. Every signature gets logged here, so anyone can check "was this signed, and when, and is that log entry still consistent" — this stops attackers from silently re-signing something under a stolen identity later

Basic flow for a Docker image:

bash

```bash
cosign sign --yes myregistry/myimage:tag
```

This signs the image, uploads the signature next to it, and records it in Rekor.

Consumer side:

bash

```bash
cosign verify myregistry/myimage:tag \
  --certificate-identity=<your CI identity> \
  --certificate-oidc-issuer=https://token.actions.githubusercontent.com
```

This confirms the image matches exactly what was signed by that identity — if it's been tampered with post-build, the hash won't match and verification fails.
